# Stellar Burgers — автотесты

Автотесты для веб-приложения [Stellar Burgers](https://stellarburgers.education-services.ru/) — сервиса по сборке и заказу бургеров.

Тесты написаны на Python с использованием Selenium WebDriver, pytest и Allure. Покрывают основную функциональность конструктора и раздел «Лента заказов». Запускаются в Google Chrome и Mozilla Firefox.

## Стек

- **Python 3.10+**
- **Selenium WebDriver** — управление браузером
- **pytest** — фреймворк для тестов
- **allure-pytest** — отчёты
- **Faker** — генерация тестовых данных
- **Page Object** — паттерн организации кода

# Запуск тестов

Все тесты (Chrome + Firefox):
pytest -v

С генерацией данных для Allure-отчёта:
pytest --alluredir=allure-results

Только один файл:
pytest tests/имя теста

Только один браузер (по имени параметра):
pytest -k "chrome"
pytest -k "firefox"

Просмотр Allure-отчёта после прогона с --alluredir=allure-results:
allure serve allure-results
Откроется браузер с интерактивным отчётом: шаги, скриншоты при падениях, группировка по тестам.

# Что проверяют тесты
Основная функциональность (test_main_functionality.py):
переход по клику на «Конструктор»;
переход по клику на раздел «Лента заказов»;
при клике на ингредиент появляется всплывающее окно с деталями;
всплывающее окно закрывается кликом по крестику;
при добавлении ингредиента в заказ счётчик этого ингредиента увеличивается.

Лента заказов (test_order_feed.py):
при создании нового заказа счётчик «Выполнено за всё время» увеличивается;
при создании нового заказа счётчик «Выполнено за сегодня» увеличивается;
после оформления заказа его номер появляется в разделе «В работе».

# Особенности реализации
Кросс-браузерность — фикстура driver в conftest.py параметризована (params=["chrome", "firefox"]), поэтому каждый тест автоматически выполняется в обоих браузерах.

Drag-and-drop через JavaScript — стандартный ActionChains не работает с HTML5 drag-and-drop в Firefox, поэтому перетаскивание ингредиента симулируется через DataTransfer и события dragstart/dragover/drop.

Ожидание реального номера заказа — в модалке после оформления сначала отображается плейсхолдер 9999, тест ждёт его смены на настоящий номер.

Нормализация номеров — номер из модалки (3889) и из «В работе» (03889) сравниваются после удаления ведущих нулей.

Никаких if/elif/else в тестах — вся логика ветвления инкапсулирована в Page Object и фикстурах; каждый тест заканчивается assert.

Тестовые данные
Учётные данные для входа хранятся в фикстуре login_credentials в conftest.py. Для генерации случайных имён, email и паролей используется data_generators.py (Faker).
